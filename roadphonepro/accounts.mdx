Pro and its included Fold device use server-authoritative sessions. The account row stores content; a session decides which account is signed in.

## What follows the phone

With `Config.UseMetadata = true`, an item stores a session pointer with a token and account ID. Trading or stealing the phone carries its existing login with it. Mail follows the signed-in RoadID account. Characters can own multiple accounts; creating an account does not permanently authorize its creator to access it.

With metadata disabled, sessions are associated with player identifiers. Follow [metadata migration](/roadphonepro/metadata#migration-from-non-metadata) when changing modes.

| Account | Item field | Session expiry |
| --- | --- | --- |
| RoadID / Cloud | `account_session` | No automatic expiry. |
| Connect | `connect_session` | 30 days after last resume, falling back to creation time. |
| Wave | `tweetwave_session` | 30 days after login. |
| Glimpse | `snapy_session` | 30 days after login by default; `Config.Snapy.SessionTTL` can override it. |
| Livestream | `livestream_session` | 30 days after login. |
| Dating | `dating_session` | No automatic expiry. |

Explicit logout ends the corresponding session. Expired social sessions return to a logged-out state on the next phone open. Only Connect uses last-resume time to calculate expiry.

## Upgrading existing accounts

Database setup runs on resource startup. The shipped `sql/account_sessions.sql`, `sql/social_sessions.sql`, `sql/livestream_sessions.sql` and `sql/dating_sessions.sql` support existing-install migrations. Back up the database and inspect startup errors before testing logins.

Older `phone_account`, `phone_twitter_account` and `phone_connect_account` blobs are read by migration logic and replaced with session pointers. Do not populate these blobs for new logins or manually copy session tokens between phones.

Dating content is keyed by profile ID. The original player identifier is not an authorization check; existing identifier-based content is migrated by the resource.

## External resources

Public RoadID lookups are **server** exports:

```lua
local account = exports['roadphone']:GetCloudAccountForSource(source)
if not account then
    return
end

local onlineSource = exports['roadphone']:GetCloudSource(account.id)
```

See [account-session exports](/roadphonepro/api/server#account-sessions). Keep account results on the server and return only fields your integration needs. A supplied account ID is not proof of login.

Other apps' internal session helpers are not automatically exports. Check the [export index](/roadphonepro/api/exports) for callable names.

For your own app, use the [custom-app RPC bridge](/roadphonepro/custom-app-rpc) and authorize operations server-side. Passwords are for authentication/account changes, not routine content requests.
