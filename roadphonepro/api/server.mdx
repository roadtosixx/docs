# Server Exports

RoadPhone Pro provides several server-side exports that allow other resources to interact with the phone system.

<Note>
  Running the SIM Card DLC? Issuing numbers, moving SIMs between phone and inventory and charging prepaid credits have their own reference: [SIM Card Exports](/roadphonepro/api/simcards).
</Note>

## Player Information

### getPlayerFromPhone

Get the framework player object for an online phone holder. For a numeric server ID, use `getSourceFromPhone`.

```lua
local player = exports['roadphone']:getPlayerFromPhone(number)
```

<ParamField path="number" type="string" required>
  The phone number to look up.
</ParamField>

<ResponseField name="returns" type="table | nil">
  The framework player object, or `nil` if not found or offline. Prefer `getSourceFromPhone` across resource boundaries because object methods do not survive serialization.
</ResponseField>

<CodeGroup>
```lua Example
local source = exports['roadphone']:getSourceFromPhone("1234567")
if source then
    print("Player found with source: " .. source)
else
    print("Player not found or offline")
end
```
</CodeGroup>

---

### getSourceFromPhone

Server ID of the player who owns a phone number. Prefer this over `getPlayerFromPhone` across resource boundaries — a framework player object loses its methods when it is serialised out of RoadPhone.

```lua

```

<ParamField path="number" type="string" required>
  The phone number to resolve.
</ParamField>

<ResponseField name="returns" type="number | nil">
  The player's server ID, or `nil` when nobody online carries that number.
</ResponseField>

<Note>
  `GetPlayerSourceByPhoneNumber(number)` does exactly the same and is kept for existing integrations.
</Note>

### getActivePhoneNumber

Read the number resolved by the phone's current server-side number logic. This never assigns a new number.

```lua
local number = exports['roadphone']:getActivePhoneNumber(source)
```

`source` is a numeric online player server ID. Returns a number string or `nil`. Metadata mode reads the active item; with the SIM addon it uses the active SIM. Legacy mode resolves the player's database number. `GetPhoneNumberBySource(source)` wraps the same resolver.

## Phone Status

Read a player's phone settings and state from the server: flight mode, silent mode, focus, power, open screen, flashlight and calls. Nothing has to be enabled for these exports.

<Note>
  **With item metadata** (`Config.UseMetadata = true`) settings belong to the phone item. Without a `number` the exports describe the phone the player is using. Pass a `number` to ask about one specific phone the player carries: the phone in the interface answers with its live values, any other phone with what is stored on its item. A number the player does not carry has no status (`nil`, or `false` for the yes/no exports).

  **Without item metadata** the player has one phone, and `number` only has to match it.
</Note>

<Tip>
  Combine it with `getSourceFromPhone` when all you have is a number:

  ```lua
  local src = exports['roadphone']:getSourceFromPhone(number)
  local status = src and exports['roadphone']:getPhoneStatus(src, number)
  ```
</Tip>

### getPhoneStatus

```lua
local status = exports['roadphone']:getPhoneStatus(source, number)
```

<ParamField path="source" type="number" required>
  The player's server ID.
</ParamField>

<ParamField path="number" type="string">
  Optional: one of the player's phone numbers (metadata mode).
</ParamField>

<ResponseField name="returns" type="table | nil">
  `nil` when the player is offline or does not carry that phone. Otherwise:

  <Expandable title="properties">
    <ResponseField name="number" type="string | nil">
      The phone's number.
    </ResponseField>
    <ResponseField name="open" type="boolean">
      The phone is on screen.
    </ResponseField>
    <ResponseField name="flightmode" type="boolean">
      Flight mode is on.
    </ResponseField>
    <ResponseField name="silent" type="boolean">
      Silent mode is on.
    </ResponseField>
    <ResponseField name="focus" type="string | nil">
      `'donotdisturb'`, `'work'`, `'personal'`, `'sleep'` or `nil`.
    </ResponseField>
    <ResponseField name="poweredOn" type="boolean">
      `false` after the player shut the phone down in Settings.
    </ResponseField>
    <ResponseField name="flashlight" type="boolean">
      The flashlight is on.
    </ResponseField>
    <ResponseField name="inCall" type="boolean">
      A call is ringing, outgoing or active, including group calls and calls to a dispatch number.
    </ResponseField>
  </Expandable>
</ResponseField>

`open`, `flashlight` and `inCall` belong to the phone in hand: for any other phone of the player they are `false`.

<CodeGroup>
```lua Phone tracking
RegisterCommand('trackphone', function(source, args)
    local number = args[1]
    local target = exports['roadphone']:getSourceFromPhone(number)
    local status = target and exports['roadphone']:getPhoneStatus(target, number)

    if not status or status.flightmode or not status.poweredOn then
        print(('%s cannot be located'):format(number))
        return
    end

    print(('%s is at %s'):format(number, GetEntityCoords(GetPlayerPed(target))))
end, true)
```
</CodeGroup>

### State bag

The values come from the player state bag `roadphoneStatus`, so other resources can also read it or react to changes. It describes the phone in the interface and is cleared when RoadPhone stops.

```lua
-- { number, open, flightmode, silent, focus, poweredOn, flashlight, groupCall }
local status = Player(source).state.roadphoneStatus

AddStateBagChangeHandler('roadphoneStatus', nil, function(bagName, _, value)
    local player = GetPlayerFromStateBagName(bagName)
    if player ~= 0 and value and value.flightmode then
        print(('%s switched flight mode on'):format(GetPlayerName(player)))
    end
end)
```

<Warning>
  The client writes this state bag, so treat it like any other client input. Prefer the exports: in metadata mode they also cover the player's other phones.
</Warning>

## Account Sessions

### GetCloudAccountForSource

```lua
local account = exports['roadphone']:GetCloudAccountForSource(source)
```

Returns the RoadID account table for the player's current server-authoritative session, or `nil` without a valid login. Use `account.id` for authorized server-side operations. Keep the full account row on the server; an item's `account_id` alone is not proof of login.

### GetCloudSource

```lua
local playerSource = exports['roadphone']:GetCloudSource(accountId)
```

Returns the online source associated with current account presence, or `nil` if unavailable. This is a presence lookup, not authorization for an arbitrary caller.

## Business Availability

### SetServiceOpen

```lua
local ok, reason = exports['roadphone']:SetServiceOpen('mechanic', true)
```

Parameters: a nonblank job name (string, at most 64 characters) and an `open` boolean. Returns `true` on success or `false, 'bad_input'` for invalid arguments. Closing a job in `Config.ServiceAlwaysOpen` returns `false, 'always_open'`.

Broadcasts the updated business status. State is held in memory and resets on resource restart. Use a job configured for your business listing.

### IsServiceOpen

```lua
local open = exports['roadphone']:IsServiceOpen('mechanic')
```

Returns a boolean. Always-open jobs return `true`; invalid jobs or businesses without an open status return `false`.

### PhoneNotifyNumber

Push a notification to a **phone number** instead of a player. This is the one you want in metadata mode: a player can carry several phones, and a notification belongs to one of them.

```lua
exports['roadphone']:PhoneNotifyNumber(phoneNumber, opts)
```

<ParamField path="phoneNumber" type="string" required>

</ParamField>

<ParamField path="opts" type="table" required>

</ParamField>

## Number Providers

Numbers that belong to no phone can be served by another resource: a phone box, a Trap Phone, a hotline. The core asks every registered provider in turn, and the first one that claims the number owns the call or message.

<Steps>
  <Step title="Register on startup">
    ```lua
    exports['roadphone']:registerNumberProvider(GetCurrentResourceName())
    ```

    <ResponseField name="returns" type="boolean">
      `true` once the resource is registered — calling it twice is harmless.
    </ResponseField>
  </Step>
  <Step title="Export the contract">
    Every function is optional; a missing one simply means "not my number".

    | Export | Signature | Returns | Description |
    |---|---|---|---|
    | `ExternalNumber_TryCall` | `fromNumber, toNumber, callerSource` | `boolean` | Take the call. `true` = handled. |
    | `ExternalNumber_TryMessage` | `fromNumber, toNumber, body` | `boolean` | Take the message. |
    | `ExternalNumber_IsReserved` | `number` | `boolean` | Does this number fall inside your range? |
    | `ExternalNumber_ResolveSource` | `number` | `source \| nil` | Who is currently reachable on it. |
    | `ExternalNumber_CallEvent` | `kind, info` | — | Call lifecycle events (`accept`, `decline`, `end`). |
  </Step>
</Steps>

<Warning>
  `ExternalNumber_IsReserved` is what stops the phone — and every SIM card — from ever issuing a number inside your range. Reserve exactly what you own: a provider that claims too much makes number generation fail for everyone.
</Warning>

<CodeGroup>
```lua Minimal provider
CreateThread(function()
    exports['roadphone']:registerNumberProvider(GetCurrentResourceName())
end)

local PREFIX = '555'

exports('ExternalNumber_IsReserved', function(number)
    return tostring(number):sub(1, #PREFIX) == PREFIX
end)

exports('ExternalNumber_TryCall', function(fromNumber, toNumber, callerSource)
    if tostring(toNumber):sub(1, #PREFIX) ~= PREFIX then return false end

    local channel = exports['roadphone']:generateCallChannelID()
    -- connect the caller with your NPC/hotline logic here
    return true
end)

exports('ExternalNumber_TryMessage', function(fromNumber, toNumber, body)
    if tostring(toNumber):sub(1, #PREFIX) ~= PREFIX then return false end
    print(('hotline SMS from %s: %s'):format(fromNumber, body))
    return true
end)
```
</CodeGroup>

## RoadDrop

### sendRoadDrop

Send a photo, a contact card or a playlist to one player's phone, exactly like an in-game RoadDrop share.

```lua
exports['roadphone']:sendRoadDrop(data)
```

<ParamField path="data" type="table" required>
  <Expandable title="properties">
    <ParamField path="playerId" type="number" required>
      Server ID of the **receiving** player.
    </ParamField>
    <ParamField path="picturelink" type="string">
      Image URL to share. Lands in the receiver's Photos app.
    </ParamField>
    <ParamField path="contact" type="table">
      Contact card: `{ firstname, lastname, number, picture }`.
    </ParamField>
    <ParamField path="playlist" type="table">
      A playlist object to share with the Music app.
    </ParamField>
    <ParamField path="roadpad" type="boolean">
      `true` delivers a shared picture to RoadPad instead of the phone.
    </ParamField>
  </Expandable>
</ParamField>

<Note>
  Exactly one content field is used per call — `picturelink`, `contact` or `playlist`, in that order of precedence. Without any of them nothing is delivered and the sender is notified.
</Note>

<Warning>
  The sender's name is resolved from the **current server event context**, not from an argument. Call this from inside a player-triggered event handler (or a command), otherwise there is no sender to resolve and the share is rejected.
</Warning>

<CodeGroup>
```lua Share a photo
RegisterServerEvent('mycam:sharePhoto')
AddEventHandler('mycam:sharePhoto', function(targetId, url)
    exports['roadphone']:sendRoadDrop({
        playerId    = targetId,
        picturelink = url,
    })
end)
```

```lua Share a contact card
exports['roadphone']:sendRoadDrop({
    playerId = targetId,
    contact  = {
        firstname = 'Marie',
        lastname  = 'Delacroix',
        number    = '4821337',
        picture   = '/public/img/user.png',
    },
})
```
</CodeGroup>

<Note>
  **Deprecated alias:** `sendAirdrop(data)` behaves identically. Use `sendRoadDrop` in new code.
</Note>

## Phone Cases (RoadPhone Studio)

RoadPhone Studio designs the case of a phone through these exports. With item metadata the design is stored on the phone item as `phone_case`, so it travels with the phone. Its `hex` colour (`'#rrggbb'`) is drawn as a rim around the phone frame the next time the phone opens.

### GetPhoneItems

Every phone item the player carries. Reads the newest state, including changes RoadPhone has buffered but not yet written to the inventory.

```lua
local result = exports['roadphone']:GetPhoneItems(source)
```

<ParamField path="source" type="number" required>
  The player's server ID.
</ParamField>

<ResponseField name="returns" type="table">
  With item metadata: `{ mode = 'metadata', phones = { { slot, item, label, number, device, form, case }, ... } }`, sorted by slot. `label` is the item name in title case (`purple_phone` becomes `Purple Phone`), `device` the item's `phone_device_id`, `form` is `'phone'` or `'fold'` and `case` the stored design or `nil`. Without item metadata the character has a single phone: `{ mode = 'character', number }`.
</ResponseField>

<Note>
  A phone item without a `phone_device_id` is given one here. An item the inventory refuses to update is left out of the list.
</Note>

---

### SetPhoneCase

Write a case design onto the phone in `slot`, but only while that slot still holds the same phone.

```lua
local ok, reason = exports['roadphone']:SetPhoneCase(source, slot, device, design)
```

<ParamField path="source" type="number" required>
  The player's server ID.
</ParamField>

<ParamField path="slot" type="number" required>
  Inventory slot of the phone, as returned by `GetPhoneItems`.
</ParamField>

<ParamField path="device" type="string" required>
  The phone's `phone_device_id` (`device` from `GetPhoneItems`). If the slot now holds a different phone, nothing is written.
</ParamField>

<ParamField path="design" type="table" required>
  The design, stored as `phone_case`. Its `hex` field (`'#rrggbb'`) sets the rim colour.
</ParamField>

<ResponseField name="returns" type="boolean, string?">
  `true`, or `false` with a reason:
  - `'no_metadata'`: `Config.UseMetadata` is off. Without item metadata RoadPhone Studio stores the design itself.
  - `'phone_changed'`: the slot is empty, holds no phone item or holds a phone with another `phone_device_id`, or `device` is not a string.
  - `'bad_design'`: `design` is not a table.
  - `'write_failed'`: the inventory refused the metadata update.
</ResponseField>

<Note>
  The design is written to the inventory at once, merged into any change RoadPhone has buffered for the same phone, so neither is lost.
</Note>

### Active phone state bags

Two replicated player state bags describe the phone in hand, so companion resources such as RoadPhone Studio can follow it on every client.

```lua
-- { slot, item, device, form } of the active phone, or nil
local active = Player(source).state.roadphoneActive

-- Network id of the phone prop in the player's hand, or nil
local propNetId = Player(source).state.roadphoneProp
```

**`roadphoneActive`** is written by the server whenever a phone item with a `phone_device_id` becomes the active phone (the player uses the item or opens the phone). `form` is `'phone'` or `'fold'`. Closing the phone does **not** clear it: it keeps describing the last phone used until another phone becomes active. It becomes `nil` when the player disconnects, when the server does not answer an open request within 5 seconds and, on Jaksam inventory, when the active phone item is removed. While an open is still looking for the right phone it can be `nil` for a moment.

**`roadphoneProp`** is written by the player's client when the hand prop is created and set back to `nil` when the prop is deleted (the phone is put away). A new prop, for example after the model changes, gets a new network id.

<Warning>
  The client writes `roadphoneProp`, so treat it like any other client input.
</Warning>
