# Metadata System

The metadata system stores phone data (contacts, messages, notes, settings) directly on the phone item in the player's inventory. This enables powerful roleplay features like phone stealing, phone trading, and owning multiple phones with separate data.

## Why Use Metadata?

<CardGroup cols={2}>
    <Card title="Phone Stealing" icon="user-x">
        When a player steals another player's phone, they can see all the victim's data - messages, contacts, photos, and more.
    </Card>
    <Card title="Phone Trading" icon="handshake">
        When a phone is given or sold to another player, all data stays on the phone and transfers with it.
    </Card>
    <Card title="Multiple Phones" icon="smartphone">
        Each phone item has its own unique phone number and data. Players can own multiple phones for different purposes.
    </Card>
    <Card title="Data Persistence" icon="database">
        Phone data is stored on the item itself, making it independent of player identity.
    </Card>
</CardGroup>

## Configuration

Open `config.lua` and configure the following options:

```lua config.lua
-- Enable the metadata system
Config.UseMetadata = true

-- 'auto' detects the running inventory. Force one only if detection picks wrong.
Config.InventorySystem = 'auto'

-- Coalesce metadata writes instead of writing on every change
Config.PhoneWriteBehind = true
Config.PhoneWriteBehindMs = 1000

-- Phone backups (recommended)
Config.BackupEnabled = true
Config.AutoBackupEnabled = false
Config.MaxBackupsPerPhone = 5
```

### Configuration Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `Config.UseMetadata` | boolean | `true` | Enable/disable the metadata system |
| `Config.InventorySystem` | string | `'auto'` | `auto`, `ox_inventory`, `one_inventory`, `jaksam`, `tgiann`, `qb-inventory`, `codem`, `core_inventory` |
| `Config.PhoneWriteBehind` | boolean | `true` | Buffer metadata writes instead of writing on every change |
| `Config.PhoneWriteBehindMs` | number | `1000` | Worst-case delay before a change is persisted |
| `Config.BackupEnabled` | boolean | `true` | Allow players to backup/restore phone data |
| `Config.AutoBackupEnabled` | boolean | `false` | Snapshot automatically on disconnect |
| `Config.MaxBackupsPerPhone` | number | `5` | Backups kept per phone number |

## Supported Inventory Systems

| Inventory | Metadata | Notes |
|---|---|---|
| `ox_inventory` | full | Remove its built-in phone item code — see below |
| `one_inventory` | full | Hooks for trade/give are wired up automatically |
| `jaksam` | full | Fully supports per-item metadata for phones |
| `tgiann` | full | Data lives in `item.info`; handled by the bridge |
| `qb-inventory` | partial | Uses `item.info` instead of `item.metadata` |
| `core_inventory` | partial | Basic metadata support |
| `codem` | limited | Not recommended for multi-phone setups |

<Note>
  Leave `Config.InventorySystem = 'auto'` unless detection picks the wrong one — the bridge checks which inventory resource is actually running.
</Note>

<Tip>
  Run `/rpselftest` in-game: it prints the detected framework, the detected inventory and whether it reports metadata support.
</Tip>

## ox_inventory Setup

When using `ox_inventory`, you need to remove some default code that interferes with RoadPhone's phone handling.

<Steps>
    <Step title="Open the ox_inventory client file">
        Navigate to: `ox_inventory/modules/items/client.lua`
    </Step>

    <Step title="Find and remove the phone code">
        Look for the `phone` item registration and remove or comment out the entire block.

        <Frame>
            <img src="https://r2.fivemanage.com/dsWPzkvn2AwNhVrA6MJWw/imouiouioiuage.png" alt="ox_inventory phone code to remove" />
        </Frame>

        The code block to remove looks similar to this:

        ```lua
        -- Remove this entire block from here
        Item('phone', function(data, slot)
        end)
        -- to here
        ```
    </Step>

    <Step title="Restart your server">
        After removing the code, restart your FiveM server for changes to take effect.
    </Step>
</Steps>

<Note>
    This step is required because ox_inventory has built-in phone handling that conflicts with RoadPhone's metadata system.
</Note>

## How It Works

### Data Flow

<Steps>
    <Step title="Player uses phone item">
        When a player uses a phone from their inventory, RoadPhone reads the metadata stored on that specific item.
    </Step>

    <Step title="Phone number assignment">
        If the phone has no number assigned, a unique number is generated and stored in the item's metadata.
    </Step>

    <Step title="Data loading">
        All phone data (contacts, messages, settings, etc.) is loaded from the item's metadata.
    </Step>

    <Step title="Data saving">
        Changes are written back to the item — buffered by `Config.PhoneWriteBehindMs` so a burst of edits becomes one write, and flushed when the phone closes.
    </Step>
</Steps>

### Multiple Phones

When a player has multiple phones in their inventory:

1. The system tracks which phone slot is currently active
2. Each phone has its own phone number and data
3. Switching phones loads the new phone's data automatically

## Metadata Structure

The item stores device data and pointers to signed-in accounts; account content remains in the database. Fields are created on demand. Fold uses the configured `phone_fold` item name, including on Jaksam; no special `phone_model` field is required. See [Fold persistence](/roadphonepro/fold#fold-and-unfold).

```lua
{
    -- Identity
    phone_number         = "1234567",     -- unique number (ignored with the SIM Card DLC)
    phone_owner          = "John Doe",    -- who it was first assigned to
    phone_assigned_date  = 1234567890,    -- unix timestamp
    phone_setup          = 1,             -- 0 = setup screen, 1 = ready
    phone_powered_on     = 1,             -- 0 = switched off

    -- Security
    phone_pin            = "123456",      -- nil when no PIN is set
    phone_pin_needed     = 1,             -- 0 = no PIN required
    phone_faceid_identifier = "license:…",-- who may unlock it with Face Unlock

    -- Look & settings
    phone_background     = "/path/to/bg",
    phone_settings       = {
        brightness = 100,                 -- 10-100
        flightmode = 0,
        darkmode = 0,
        large_app_icons = 0,
        iconcolor = "light",              -- "light" or "dark"
        timeCustomization = nil,          -- lockscreen clock + widget layout
        iconPack = "default",              -- default, studio, outline, monochrome
        iconShape = "square",              -- square or round
        unfolded = false,                 -- saved Fold state
    },
    phone_apps           = { ... },        -- installed apps + homescreen layout
    phone_chat_backgrounds = { ... },      -- per-conversation wallpapers

    -- Content
    phone_contacts       = { ... },
    phone_notes          = { ... },
    phone_photos         = { ... },
    phone_albums         = { ... },
    phone_alarms         = { ... },
    phone_calendar_events = { ... },
    phone_reminders      = { ... },
    phone_reminder_lists = { ... },
    phone_radio_channels = { ... },        -- saved frequencies
    phone_radio_recent   = { ... },
    phone_bank_iban      = "DE123456",
    phone_bank_favorites = { ... },
    phone_darkchat       = { ... },        -- joined rooms
    phone_darkchat_unread = { ... },
    phone_groups_unread  = { ... },
    phone_customapp_data = { ... },        -- storage of custom apps

    -- Sessions: which account this phone is signed in to
    account_session      = { token = "…", account_id = 12 },  -- RoadID / cloud
    connect_session      = { ... },
    tweetwave_session    = { ... },
    snapy_session        = { ... },
    livestream_session   = { ... },
    dating_session       = { ... },
    loop_session         = { ... },

    -- Hardware add-ons
    phone_sims           = { ... },        -- SIM Card DLC
    phone_active_sim     = 1,
    phone_battery        = 87,             -- Battery system
}
```

<Warning>
  `phone_account` and `phone_twitter_account` are legacy fields. Current account identity comes from server-authoritative sessions. Do not use these fields for login or logout.
</Warning>

### Limits

Arrays are capped so an item's metadata cannot grow without bound (`server/phone_metadata.lua`):

| Field | Limit | Field | Limit |
|---|---|---|---|
| messages | 300 | photos | 150 |
| contacts | 200 | albums | 30 |
| notes | 150 | installed apps | 100 |
| alarms | 30 | calendar events | 100 |
| radio channels | 30 | reminders | 200 |
| recent radio | 15 | reminder lists | 20 |
| bank favourites | 20 | chat backgrounds | 60 |

When a limit is reached, the oldest entry is dropped.

### Writes are buffered

Changes are coalesced instead of hitting the inventory on every keystroke:

```lua config.lua
Config.PhoneWriteBehind = true
Config.PhoneWriteBehindMs = 1000  -- worst-case persistence delay
```

That is why another resource reading the item immediately after a change can still see the old value. Force a write first:

```lua
exports['roadphone']:PhoneWriteBehind_Flush(source)
```

## Backup System

With `Config.BackupEnabled = true`, players can backup and restore their phone data.

### Features

- **Manual Backups**: Players can create backups anytime
- **Backup Naming**: Custom names for easy identification
- **Restore**: Restore any previous backup to current phone
- **Limit**: `Config.MaxBackupsPerPhone` per phone number (default 5)

### Use Cases

- Before giving away a phone, backup the data
- Restore data to a new phone after losing the old one
- Keep multiple backup points for important data

<Note>
  SIM cards (`phone_sims`, `phone_active_sim`) and the battery level are deliberately left out of backups. They are hardware state — restoring them would duplicate SIM cards and hand out free charge.
</Note>

## Troubleshooting

<AccordionGroup>
    <Accordion title="Phone data doesn't save">
        **Possible causes:**
        - `Config.UseMetadata` is set to `false`
        - Inventory system doesn't support metadata
        - Wrong `Config.InventorySystem` value

        **Solution:** Verify your config matches your actual inventory system.
    </Accordion>

    <Accordion title="Wrong phone data loads">
        **Possible causes:**
        - Active phone slot tracking issue
        - Player has multiple phones

        **Solution:** Ensure the player is using the correct phone from their inventory.
    </Accordion>

    <Accordion title="ox_inventory phone not working">
        **Possible causes:**
        - Default phone code not removed from ox_inventory
        - Conflicting phone resource

        **Solution:** Follow the ox_inventory setup steps above to remove the conflicting code.
    </Accordion>

    <Accordion title="Phone number changes randomly">
        **Possible causes:**
        - Metadata not saving properly
        - Inventory system issue

        **Solution:** Check server console for errors related to metadata updates.
    </Accordion>
</AccordionGroup>

## Migration from Non-Metadata

If you're switching from the non-metadata system to metadata:

<Warning>
    Existing phone data stored in the database will not automatically transfer to item metadata. Players will start with fresh phones.
</Warning>

### Migration Options

1. **Fresh Start**: Simply enable metadata - all phones start fresh
2. **Manual Migration**: Use the `/phonemigrate` command (see [Phone Migrate](/roadphonepro/commands/migrate))
3. **Backup First**: Have players backup important data before migration
