RoadPad v3 uses the RoadPhone Pro custom-app system inside the tablet. Configure the tablet's own catalogue in `roadpad/public/static/config/config.json`. In linked mode, shared backend operations use the connected phone session.

## Register an app

Add one object to the existing `AppStore` array. This is an example fragment; do not replace the rest of your catalogue:

```json roadpad/public/static/config/config.json
{
  "AppStore": [
    {
      "name": "Tablet Dashboard",
      "light_icon": "/public/img/Apps/light_mode/custom.webp",
      "dark_icon": "/public/img/Apps/dark_mode/custom.webp",
      "default": true,
      "category": "apps",
      "custom_app_id": "TABLET_DASHBOARD",
      "redirect": "custom_app",
      "url": "https://cfx-nui-my-tablet-app/html/index.html",
      "darkmode": false,
      "allowJobs": [],
      "disallowJobs": [],
      "custom_event": {
        "active": false,
        "closeWhenOpenApp": false
      }
    }
  ]
}
```

| Field | Purpose |
| --- | --- |
| `name` | Display name shown on the home screen and in the App Shop. |
| `light_icon` / `dark_icon` | Icons for the light and dark icon styles. |
| `default` | `true` preinstalls the app; `false` lets players install it from the App Shop. |
| `category` | `apps` or `games`. |
| `custom_app_id` | A unique, stable ID. Use a different value for every custom app. |
| `redirect` | Keep `custom_app` for this type of app. |
| `url` | The page loaded in the app frame. Replace the example with your own resource/page. |
| `darkmode` | App display contrast setting. |
| `allowJobs` / `disallowJobs` | Job restrictions for opening the app. Server operations must still validate permissions. |
| `custom_event` | Optional Lua action when the icon is opened. |

For an App Shop listing, also add an `AppInfos` entry matched by `redirect` and `custom_app_id`. See the [shared registration and AppInfos reference](/roadphonepro/custom-apps).

## Serve a local app

Your app resource must expose its HTML, scripts, styles and assets through its manifest. The URL's resource name must match its installed folder:

```lua my-tablet-app/fxmanifest.lua
fx_version 'cerulean'
game 'gta5'

files {
    'html/index.html',
    'html/app.js',
    'html/style.css',
}
```

Start the app resource before RoadPad. A resource displayed in RoadPad's iframe does not need its own `ui_page`. An external website must allow iframe embedding; opening it in a normal browser does not prove that it can be embedded.

## Shared JavaScript API and server RPC

Supported custom apps use the shared `window.roadphone` API. Follow the [Custom App API](/roadphonepro/custom-apps) and [server RPC guide](/roadphonepro/custom-app-rpc) for initialization, storage, permissions and server calls.

Use a demo/template compatible with the installed RoadPad build. When using a template that supports both products, let it resolve the active host rather than hard-coding every NUI request to `https://roadphone/`. The tablet's host resource is `roadpad`.

Ordinary pages in the Browser and tablet website apps do not gain access to the native UI message dispatcher. Build native integration through the supported custom-app API, and validate ownership, jobs and money actions on the server.

## Optional Lua action on open

Set `custom_event.active` to `true` to invoke the existing `app_custom_event` callback with the app's display name. With `closeWhenOpenApp: true`, the icon closes the tablet instead of opening an iframe.

Edit the **existing** callback in RoadPad's editable `client/clientAPI.lua`; keep a single registration and always answer its NUI callback:

```lua roadpad/client/clientAPI.lua
RegisterNUICallback('app_custom_event', function(data, cb)
    if data.app == 'Tablet Dashboard' then
        TriggerEvent('my-tablet-app:open')
    end

    cb('ok')
end)
```

The target event must be implemented by your own app resource. This action is not authorization for a server operation.

## Update and test

Keep your app resources and restore their catalogue entries when updating RoadPad. Separately sold Custom Apps require their own installation.

Test portrait and landscape, narrow and wide content, scrolling, light/dark display, closing/reopening, job restrictions and switching between two paired devices. Per-device storage and server requests must follow the phone currently connected to that tablet.
