<AccordionGroup>
  <Accordion title="Which RoadPhone version do I need?" icon="smartphone">
    Linked mode needs a RoadPhone Pro build containing the RoadPad companion exports and session/metadata integration. Update both resources together and restart RoadPhone before RoadPad. A matching or similar version number alone does not prove compatibility.

    RoadPad and RoadPhone use separate version numbers. An older-version warning comparing RoadPhone 2.x to RoadPad 3.x can therefore be misleading; check the companion integration and the actual pairing error. See [Updating to v3](/roadpad/updates).
  </Accordion>

  <Accordion title="Can I use RoadPad without RoadPhone?" icon="tablet">
    Yes. If RoadPhone is not running when RoadPad starts, the tablet uses its own backend and configuration. If you start or stop RoadPhone later, restart RoadPad to choose the appropriate mode. Follow the [standalone installation steps](/roadpad/installation).
  </Accordion>

  <Accordion title="How do I pair multiple phones and tablets?" icon="link">
    Enable metadata in the active backend and make every tablet non-stackable. Use the specific tablet item, then choose its phone. Each tablet keeps its own pairing. M and `/roadpad` reopen the last selected tablet; use another inventory item to change the physical tablet.

    Tap **Connected** in the status bar to manage or remove a pairing. See [Pairing & Metadata](/roadpad/pairing).
  </Accordion>

  <Accordion title="The tablet says it is no longer in my inventory" icon="package">
    Check that you still carry the specific tablet you selected earlier. A hotkey reopens that selection; carrying a different tablet does not silently replace it. Use the other tablet item explicitly.

    If the correct item is present, check RoadPad's `Config.Items`, the detected inventory adapter and whether its item metadata is being persisted. In linked mode, metadata and inventory settings come from RoadPhone.

    If no tablet is present, the rejection is correct. An older client could still display the pairing screen after the server returned `tablet_missing`. Install the RoadPad inventory-opening fix in both its client and server files: the UI should stay closed and only the missing-item notification should appear. Disabling metadata does not correct that UI bug.
  </Accordion>

  <Accordion title="Why does RoadPad ask me to separate a tablet stack?" icon="layers">
    Metadata mode gives each physical tablet its own identity. Multiple tablets in one stack cannot share that identity. Set `stack = false` for ox_inventory, or the equivalent unique-item option in your inventory, and separate existing stacks into individual slots.
  </Accordion>

  <Accordion title="No phones appear in the device picker" icon="smartphone">
    Carry a RoadPhone recognized by RoadPhone's configured item list. Verify that RoadPhone is running, has the current companion integration and detects the correct inventory. If a phone identity cannot be saved to its item, that device cannot be offered for pairing.

    Check the server console for inventory/metadata errors. Phones with an unusable state may appear disabled. Keep both the tablet and chosen phone in the inventory.
  </Accordion>

  <Accordion title="The paired phone is missing or the connection was lost" icon="unplug">
    Return the paired phone to the inventory, then reopen the tablet or refresh the device picker. RoadPad keeps the saved binding instead of choosing another phone automatically.

    To change the connection deliberately, use **Connected** and choose a different carried phone. Moving items between slots should preserve the link because device IDs, rather than slots or phone numbers, identify them.
  </Accordion>

  <Accordion title="Settings or messages do not match the phone" icon="refresh-cw">
    Confirm that you opened the tablet paired with the expected phone. Close the current device normally so pending changes can finish, then reopen the target device.

    If settings report a save failure, retry closing instead of forcing a device switch. Verify metadata writes and install compatible updates for both resources. Test with a note/setting on two separately paired phones; reconnecting should load the selected device's current data.
  </Accordion>

  <Accordion title="Changing RoadPad's Lua config seems to do nothing" icon="settings">
    Linked mode takes shared settings, including metadata, inventory, locale defaults and service options, from RoadPhone. Tablet item names, controls, prop and tablet-specific app settings remain in RoadPad. The frontend catalogue is always RoadPad's own `public/static/config/config.json`.

    Use the [configuration ownership table](/roadpad/configuration), then restart the affected resources.
  </Accordion>

  <Accordion title="How do I change the key, language or available apps?" icon="keyboard">
    Change tablet key defaults in `roadpad/config.lua`; players with an existing binding can update it in FiveM's key-binding settings. M is the supplied default.

    Set `Config.Locale` in the active backend for its default language, or choose the interface language in Settings. App display names and the `AppStore` catalogue are configured in RoadPad's `public/static/config/config.json`. See [Configuration](/roadpad/configuration).
  </Accordion>

  <Accordion title="Photos or videos are not saved" icon="image">
    Check the upload method and credentials in the backend that is actually running: RoadPhone in linked mode, RoadPad in standalone mode. Uploads use the configured media provider; Discord log webhooks are not a replacement for its upload key.

    Follow [Fivemanage setup](/roadpad/fivemanage), then check the upload response, provider access and storage limits.
  </Accordion>

  <Accordion title="I cannot hear music" icon="music">
    Start the supplied `xsound` dependency before the active backend. Check GTA music volume and the Windows volume mixer. If another resource, such as a loading screen, muted shared media playback, unmute it there.

    In linked mode, RoadPhone owns phone world audio and the call/voice connection; verify the phone's audio configuration as well.
  </Accordion>

  <Accordion title="The mouse is stuck or the tablet prop remains visible" icon="mouse">
    For stuck mouse input, try **Settings > Keyboard/Mouse > Mouse Input Method > Raw Input** in GTA/FiveM.

    Close RoadPad normally first. `/stoptablet` closes it and `/fixtabletprop` runs the prop cleanup command. If it remains stuck, include the preceding F8/server errors in your report.
  </Accordion>

  <Accordion title="I found a bug — what should I include?" icon="bug">
    Report it in [RoadShop Discord](https://discord.gg/2nZrmmvM2q) with both resource versions, operating mode, framework/inventory, metadata setting and exact reproduction steps. Include the relevant F8 and server errors with private API keys and personal information removed.

    For pairing issues, say which inventory item was used, which phone was selected, whether either item moved or left the inventory, and whether you opened through the item, M or a command.
  </Accordion>
