# FAQ

## Start here

Before anything else, run this in your **server console**:

```bash
roadvr diag
```

It checks the bridge and framework, ox_lib, oxmysql, your inventory, the
locale, the valet price, `Config.FirstPersonOnly`, the `roadvr_profiles` table,
whether every Beat song file is in place, and the optional xsound and RoadPhone
integrations — and it names which one is unhappy. Most of the accordions below
are things `roadvr diag` will tell you outright.

## Installation

<AccordionGroup>
  <Accordion title="Where do I enter my transaction ID?">
    Nowhere. RoadVR has no license key step. In RoadVR, `API.lua` is the
    **exports file for other developers**, not a place to put credentials — it
    is in `escrow_ignore` precisely so people can read it.

    If you are used to RoadPad or RoadPhone, this is the one thing that is
    different.
  </Accordion>

  <Accordion title="RoadVR does not start at all">
    RoadVR declares three dependencies and FiveM refuses to start it without
    them: **OneSync**, **ox_lib** and **oxmysql**. Check that OneSync is on and
    that both resources are ensured before `roadvr`.
  </Accordion>

  <Accordion title="Do I have to import the SQL file?">
    No. Every table is created on first start, and an older installation has
    missing columns added automatically.

    The SQL files ship for two cases only: a database user without `CREATE`
    permission, and a server owner who wants to read the schema before a script
    touches their database. See [About the
    database](/roadvr/installation#about-the-database).
  </Accordion>

  <Accordion title="The headset switches itself off with a profile error">
    The player's profile could not be loaded from the database in time. Check
    the oxmysql connection and the server console for database errors — RoadVR
    turns the headset off rather than letting a player edit a profile that
    never arrived.
  </Accordion>

  <Accordion title="Players wear the wrong glasses, or none">
    `roadvr_models` is not running. It streams the headset the player wears and
    the one carried between hands and head. Ensure it before `roadvr`.

    Peds without a glasses slot need `Config.Visor.mode = 'prop'` — see
    [Configuration](/roadvr/configuration#the-headset).
  </Accordion>

  <Accordion title="Which frameworks are supported?">
    ESX, QBCore, Qbox and standalone. RoadPhone is detected when present but is
    **not** a requirement. It has to be version **2.6.0 or newer** — older
    versions are treated as no RoadPhone at all.
  </Accordion>

  <Accordion title="roadvr diag reports xsound as missing">
    That line is informational. No RoadVR feature needs xsound.
  </Accordion>
</AccordionGroup>

## Getting in

<AccordionGroup>
  <Accordion title="The item does nothing">
    Check that the item name in your inventory matches `Config.Item`
    (`roadvr_headset` by default), and that the item is registered as
    **usable**. RoadVR registers the usable item itself, but the item has to
    exist in your inventory's item list first.

    The player also has to be in **first person** — otherwise they get *"RoadVr
    only works in first-person view."*
  </Accordion>

  <Accordion title="The headset comes off when I switch the camera">
    That is `Config.FirstPersonOnly`. First person is the condition for putting
    the headset on, and for keeping it on. Set it to `false` to allow every
    view.
  </Accordion>

  <Accordion title="I want to run it without an item">
    Set `Config.Item = ''`. Everybody can then use the headset, and the way in
    is `/roadvr_toggle` or the FiveM keybind of the same name. On a standalone
    server this is the only way, because there are no usable items.
  </Accordion>

  <Accordion title="The roadvr_toggle keybind has no key">
    That is deliberate. A default would take a key away from every server that
    installs RoadVR. Players bind it once themselves under Settings → Key
    Bindings → FiveM.
  </Accordion>

  <Accordion title="F7 does nothing">
    F7 only works while the headset is on. In a car with the cockpit bar, F7
    shows and hides the bar instead of the home screen. If neither happens,
    another resource has taken F7 — rebind it in the FiveM key settings.
  </Accordion>
</AccordionGroup>

## Using it

<AccordionGroup>
  <Accordion title="I cannot click anything">
    You are in passthrough. Look at a window and press `E` to focus it — that
    is what frees the mouse. `ESC` goes back.
  </Accordion>

  <Accordion title="G does not open the widgets any more">
    The widget key ships unbound. Open the editor with the **Widgets** button
    under the home screen, the **Widgets** switch in the Control Centre, or
    `/roadvr_widgets` — and bind a key to it in the FiveM key settings if you
    want one back.
  </Accordion>

  <Accordion title="The interface is in the wrong language">
    `Config.Locale` sets the language of Lua-side messages — notifications and
    errors — and is the interface language for everybody who has not picked
    their own. Once a player chooses a language in Settings → General, their
    choice wins for the interface.

    A player seeing English windows on a German server is not a bug; it is
    their setting.
  </Accordion>

  <Accordion title="A window will not stay where I put it">
    Check its anchor. **Come along** follows the player, **Stay in place**
    stays put. Every window has its own anchor button in the bar below it, and
    each player sets the default for new windows in Settings → Windows.
  </Accordion>

  <Accordion title="A widget will not stick to a surface">
    Four reasons, in order of likelihood:

    - the surface is tilted more than `Config.Widgets.maxSurfaceTilt` and counts
      as floor or ceiling
    - that spot already carries `Config.Widgets.maxPerCluster` widgets (3)
      within `clusterRadius` (5 m) — the notification says *"that spot already
      has enough widgets on it"*
    - you are further away than `Config.Widgets.reach` (6 m)
    - you already have `Config.Widgets.max` widgets up (12)
  </Accordion>

  <Accordion title="My widgets disappeared">
    Look at the distance first — beyond `Config.Widgets.renderDistance` (10 m)
    a widget is not drawn, but it is still saved.

    They also step aside once `Config.Widgets.hideAtPanels` app windows are in
    view at the same time (3 by default), and they are hidden while an
    environment runs unless **Widgets in an environment** is on in Settings →
    Comfort.
  </Accordion>

  <Accordion title="Opening an app closed another one">
    `Config.MaxPanels` (4) app windows can be open at once. Opening a fifth
    closes the oldest, with a notification saying so.
  </Accordion>

  <Accordion title="A valet delivery failed but the fee was charged">
    A confirmed valet fee stays charged if the delivery fails later. There is
    no automatic refund.
  </Accordion>
</AccordionGroup>

## Environments

<AccordionGroup>
  <Accordion title="The Environments app says no landscapes are enabled">
    `Config.Environments.list` is empty — usually an old `config.lua` from the
    panorama days. Put the three built-in landscapes back; see
    [Environments](/roadvr/environments#configuration).
  </Accordion>

  <Accordion title="An app refuses to open while an environment runs">
    `Config.Environments.blockedApps` — basketball, beat, chess, darts, drone
    and the map by default. Each of them puts something into the **world**, and
    the landscape is exactly what stands between the player and the world.
  </Accordion>

  <Accordion title="Where did the panoramas go?">
    Panorama images were replaced by three built-in 3D landscapes. Entries with
    `image` are ignored and `public/environments/` is no longer read. See
    [Coming from panoramas](/roadvr/environments#coming-from-panoramas).
  </Accordion>
</AccordionGroup>

## Updates

<AccordionGroup>
  <Accordion title="How do I know a new version is out?">
    With `Config.Updates.enabled`, the server checks RoadVR's public version
    file on start and every `intervalMinutes`. The console announces a new
    release, and players see it under **Settings → Updates** with the release
    notes. Nothing is installed automatically.
  </Accordion>

  <Accordion title="Do I lose my config when I update?">
    Not if you keep your `config.lua`. Every block you do not add from the new
    version falls back to the shipped default, and the console names the
    missing blocks. See [Updating](/roadvr/installation#updating).
  </Accordion>
</AccordionGroup>

## Performance

<AccordionGroup>
  <Accordion title="The frame rate drops with a lot of windows open">
    `Config.MaxPanels` (4) caps app windows and `Config.Widgets.max` (12) caps
    widgets. Both exist for this reason. `Config.Widgets.hideAtPanels` sheds
    the decoration automatically once the workspace fills up.
  </Accordion>

  <Accordion title="The map table stutters">
    Unthrottled, the map's textures take about 420 MB of video memory. Halve
    `Config.Gps.texture.base` first.
  </Accordion>

  <Accordion title="Windows trail behind when I turn my head quickly">
    The windows are drawn by the interface, separately from the game's own
    frame, so on a very fast turn they can trail slightly. How much depends on
    frame timing and hardware — a steady frame rate keeps it small.
  </Accordion>
</AccordionGroup>

## Developers

<AccordionGroup>
  <Accordion title="Can I add my own app without editing RoadVR?">
    Yes, and that is the supported way. Your own resource registers an HTML
    page and it appears on the home screen — RoadVR is not modified, so an
    update overwrites nothing.

    See [Custom Apps](/roadvr/custom-apps), [Custom
    Widgets](/roadvr/custom-widgets) and [Custom Games](/roadvr/custom-games).
  </Accordion>

  <Accordion title="Can my app read the theme, the language or its window size?">
    Yes — that is what the [SDK](/roadvr/api/sdk) is for. It also tells your
    page when its window is about to close.
  </Accordion>

  <Accordion title="Where is the full export list?">
    In `API.lua` inside the resource. It is in `escrow_ignore`, so it is
    readable. The same list with parameters is at [Client
    API](/roadvr/api/client).
  </Accordion>

  <Accordion title="Can I build the Vue interface myself?">
    No. The shipped package contains the built interface in `public/` and no
    `ui/` folder — which is also why custom apps are loaded as pages rather
    than compiled in.
  </Accordion>
</AccordionGroup>
