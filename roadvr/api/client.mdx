# Client API

Every export below is client-side. Apart from the three headset exports, they
live in `API.lua` inside the resource. That file is in `escrow_ignore`, so you
can read the source of everything from [Panels](#panels) down.

The one server-side export, `registerRoadVrGame`, is documented in the [Game
SDK](/roadvr/api/game-sdk).

## Headset

### isRoadVrActive

Is RoadVR running for this player?

<ResponseField name="return" type="boolean">
  `true` whenever the state is anything but `off` — including while the headset
  is still booting or already shutting down. Test `getRoadVrState()` for
  `'passthrough'` if you need to know the player can act right now.
</ResponseField>

```lua
local active = exports.roadvr:isRoadVrActive()
```

### getRoadVrState

The state machine, as a string.

<ResponseField name="return" type="string">
  `off`, `booting`, `passthrough`, `focus` or `shutdown` — and a few more that
  hold the cursor while a feature runs: `widgets` (the widget editor), `beat`,
  `minigolf`, `shooter` and `game`. More may be added.

  `passthrough` is windows floating while the player moves normally. `focus` is
  the mode in which the mouse is free and the player can click.
</ResponseField>

```lua
-- Test for the one state you need rather than listing the others: the next
-- state RoadVR adds would otherwise be a bug in your code.
if exports.roadvr:getRoadVrState() == 'passthrough' then
    -- the player can move and act normally
end
```

### putVisorOn

Puts the visor on **another** ped's head.

<ParamField path="ped" type="number" required>
  The ped handle to fit the visor to.
</ParamField>

<ResponseField name="return" type="table | nil">
  A handle you keep for `takeVisorOff`. `nil` when nothing was possible on that
  ped.
</ResponseField>

```lua
local handle = exports.roadvr:putVisorOn(somePed)
if not handle then return end
```

<Info>
  This exists for scene work — actors who should be wearing the headset without
  the calling resource having to know anything about head bones, offsets or
  addon clothing. It does not start a session for that ped.
</Info>

### takeVisorOff

<ParamField path="handle" type="table" required>
  The handle `putVisorOn` returned.
</ParamField>

```lua
exports.roadvr:takeVisorOff(handle)
```

## Notifications

### showRoadVrNotification

Shows a notification card in the headset — the same card RoadVR's own messages
use, collected in the Control Centre.

<ParamField path="data" type="table" required>
  <Expandable title="Properties">
    <ParamField path="title" type="string">
      Up to 160 bytes.
    </ParamField>
    <ParamField path="message" type="string">
      Up to 4000 bytes. `description` is accepted as another name for it.
    </ParamField>
    <ParamField path="duration" type="number">
      Milliseconds, held between 1000 and 30000.
    </ParamField>
  </Expandable>
</ParamField>

<ResponseField name="handled" type="boolean">
  `true` when the headset took the notification. `false` when nobody is wearing
  one, the headset is still booting or shutting down, or there is no text — show
  your normal notification then.
</ResponseField>

```lua
local handled = exports.roadvr:showRoadVrNotification({
    title = 'Garage',
    message = 'Your car has been repaired.',
    duration = 6000,
})

if not handled then
    -- your usual notification
end
```

<Note>
  Text is plain. GTA colour codes such as `~r~` and HTML tags are removed;
  `~n~` and `<br>` become line breaks. Over-long text is cut at the limit.
</Note>

## Panels

### openRoadVrPanel

Opens a window for a registered app.

<ParamField path="appId" type="string" required>
  A registered app id — one of RoadVR's own, or one you registered yourself.
</ParamField>

<ParamField path="opts" type="table">
  <Expandable title="Properties">
    <ParamField path="anchor" type="string">
      `'body'` follows the player, `'world'` stays put. Omit it and the
      player's own setting decides — which is usually what you want.
    </ParamField>

    <ParamField path="size" type="table" default="{ w = 1.2, h = 0.75 }">
      Window size in **metres**. The size an app was registered with is not
      used here — only the home screen applies it — so pass it again.
    </ParamField>

    <ParamField path="distance" type="number">
      How far in front of the player it opens, in metres.
    </ParamField>
  </Expandable>
</ParamField>

<ResponseField name="panelId" type="string | nil">
  `nil` when the headset is off. If the same app is already open, that window
  is closed and the new one gets a new id. At `Config.MaxPanels` the oldest
  window is closed to make room.
</ResponseField>

```lua
local panelId = exports.roadvr:openRoadVrPanel('myres_shop', {
    anchor   = 'world',
    size     = { w = 1.6, h = 0.9 },
    distance = 2.5,
})
```

### closeRoadVrPanel

<ParamField path="panelId" type="string" required>
  The id `openRoadVrPanel` returned.
</ParamField>

```lua
exports.roadvr:closeRoadVrPanel(panelId)
```

## Custom apps

Full guide: [Custom Apps](/roadvr/custom-apps).

### registerRoadVrApp

<ParamField path="def" type="table" required>
  <Expandable title="Properties">
    <ParamField path="id" type="string" required>
      Unique. Prefix it with your resource name, and never reuse the id of a
      built-in app — `shooter`, `reminders` and `darts` are refused outright.
    </ParamField>
    <ParamField path="page" type="string" required>
      A file in **your** resource, e.g. `'ui/index.html'`.
    </ParamField>
    <ParamField path="name" type="string" default="the id">
      Shown under the icon.
    </ParamField>
    <ParamField path="icon" type="string | table">
      A file in your resource, e.g. `'ui/icon.png'` — or a pair,
      `{ dark = 'ui/icon-dark.svg', light = 'ui/icon-light.svg' }`, to follow
      the player's icon style the way the built-in apps do. Name every file you
      pass in your own `files {}` block.
    </ParamField>
    <ParamField path="size" type="table" default="{ w = 1.2, h = 0.75 }">
      Metres. Applied when the app is opened from the home screen.
    </ParamField>
    <ParamField path="hidden" type="boolean" default="false">
      Keep it off the home screen and open it yourself.
    </ParamField>
  </Expandable>
</ParamField>

<ResponseField name="ok" type="boolean">
  `false` when the id already belongs to another resource or is refused.
  Registering again from your own resource replaces your earlier definition.
</ResponseField>

<ResponseField name="err" type="string">
  `'definition is not a table'`, `'missing id'`, `'missing page'`,
  `'reserved built-in id'` or `'id "<id>" already belongs to <resource>'`.
</ResponseField>

```lua
local ok, err = exports.roadvr:registerRoadVrApp({
    id   = 'myres_shop',
    page = 'ui/index.html',
    name = 'Shop',
})
```

### unregisterRoadVrApp

Removes the app and closes its window if it is open. Not needed on resource
stop — that is cleaned up on its own.

<ResponseField name="return" type="boolean">
  `false` when the id is not yours.
</ResponseField>

```lua
exports.roadvr:unregisterRoadVrApp('myres_shop')
```

### sendToRoadVrApp

Sends data into your app's window. It arrives as a `message` event carrying
`{ source: 'roadvr', ...payload }`.

<ResponseField name="return" type="boolean">
  `true` when the id is yours, `false` when it is not. A message to a closed
  window is dropped quietly — **normal, not an error**. Your resource has no idea
  whether the player has your app open.
</ResponseField>

```lua
exports.roadvr:sendToRoadVrApp('myres_shop', { type = 'tick', speed = 42 })
```

## Custom widgets

Full guide: [Custom Widgets](/roadvr/custom-widgets).

### registerRoadVrWidget

<ParamField path="def" type="table" required>
  <Expandable title="Properties">
    <ParamField path="id" type="string" required>
      Unique. Prefix it with your resource name.
    </ParamField>
    <ParamField path="page" type="string" required>
      A file in **your** resource, e.g. `'ui/widget.html'`.
    </ParamField>
    <ParamField path="name" type="string" default="the id">
      Shown under the tile in the widget bar.
    </ParamField>
    <ParamField path="icon" type="string">
      A file in your resource.
    </ParamField>
    <ParamField path="size" type="number" default="0.34">
      Metres of **width**. The height follows from `aspect`.
    </ParamField>
    <ParamField path="min" type="number" default="0.2">
      Smallest width the wheel allows, in metres.
    </ParamField>
    <ParamField path="max" type="number" default="0.8">
      Largest width the wheel allows, in metres.
    </ParamField>
    <ParamField path="aspect" type="number" default="1.0">
      Width divided by height.
    </ParamField>
    <ParamField path="mount" type="string" default="recess">
      `'recess'` sinks it into the wall, `'raised'` stands it off.
    </ParamField>
    <ParamField path="shape" type="string" default="rounded">
      `'round'` or `'rounded'`. Recess only.
    </ParamField>
  </Expandable>
</ParamField>

<ResponseField name="ok" type="boolean">
  `false` when the id already belongs to another resource.
</ResponseField>

<ResponseField name="err" type="string">
  Why it failed, when it did.
</ResponseField>

```lua
local ok, err = exports.roadvr:registerRoadVrWidget({
    id   = 'myres_gauge',
    page = 'ui/widget.html',
    name = 'Gauge',
})
```

### unregisterRoadVrWidget

<Warning>
  Widgets already hanging are **left on the wall**. They are in the player's
  profile, and a resource going away is not a reason to clear somebody's room —
  they fall back to an *unavailable* plate until it returns.
</Warning>

<ResponseField name="return" type="boolean">
  `false` when the kind is not yours.
</ResponseField>

```lua
exports.roadvr:unregisterRoadVrWidget('myres_gauge')
```

### sendToRoadVrWidget

Reaches **every** widget of this kind that is currently drawn. Arrives as
`{ source: 'roadvr', widget: '<id>', ...payload }`.

<ResponseField name="return" type="boolean">
  `false` when the kind is not yours.
</ResponseField>

```lua
exports.roadvr:sendToRoadVrWidget('myres_gauge', { rpm = 3400 })
```

### getRoadVrWidgetInstances

Which widgets of your kind are on a wall right now.

<ResponseField name="return" type="table">
  A list of instance ids. An empty table is a normal answer — the player may
  simply not have hung one.
</ResponseField>

```lua
local ids = exports.roadvr:getRoadVrWidgetInstances('myres_gauge')

-- Check before you start sending. Nothing hanging means nothing to send to,
-- and that check is the difference between a widget that costs nothing when
-- unused and one that does not.
if #ids == 0 then return end
```

## World markers

Full guide: [Custom Markers](/roadvr/custom-markers). Markers do not survive a
RoadVR restart — add them again in `onClientResourceStart` for `roadvr`.

### addRoadVrMarker

<ParamField path="def" type="table" required>
  <Expandable title="Properties">
    <ParamField path="kind" type="string" required>
      `'label'`, `'arrow'`, `'outline'` or `'path'`. Fixed once created.
    </ParamField>
    <ParamField path="pos" type="vector3">
      A fixed point in the world. `pos` or `entity`, never both.
    </ParamField>
    <ParamField path="entity" type="number">
      An existing entity the marker follows. Required for `'outline'`.
    </ParamField>
    <ParamField path="points" type="table">
      `'path'` only: at least two `vector3`.
    </ParamField>
    <ParamField path="text" type="string">
      `'label'` needs one, `'arrow'` may have one. Your text, localised by you.
    </ParamField>
    <ParamField path="color" type="string" default="the player's accent">
      `'#rrggbb'`.
    </ParamField>
    <ParamField path="throughWalls" type="boolean" default="false">
      `false` hides it behind geometry the way a window is hidden.
    </ParamField>
    <ParamField path="fadeDistance" type="number">
      Metres, capped by `Config.Markers.cullDistance`.
    </ParamField>
  </Expandable>
</ParamField>

<ResponseField name="id" type="string | nil">
  The marker's handle, or `nil` with a reason as the second value.
</ResponseField>

```lua
local id, err = exports.roadvr:addRoadVrMarker({
    kind = 'label',
    pos = vector3(215.8, -810.1, 30.7),
    text = 'Meeting point',
})
```

### updateRoadVrMarker

Patches any field except `kind`. A patch follows the same rules as a definition
and fails with the same kind of reason.

<ResponseField name="ok" type="boolean">
  `false` for an unknown handle — normal after a RoadVR restart — or a patch
  that breaks a rule, with the reason as the second value.
</ResponseField>

```lua
exports.roadvr:updateRoadVrMarker(id, { text = 'Meeting point — 2 min' })
```

### removeRoadVrMarker

<ResponseField name="return" type="boolean">
  `false` for an unknown handle, quietly.
</ResponseField>

```lua
exports.roadvr:removeRoadVrMarker(id)
```

### clearRoadVrMarkers

Removes all markers of your resource. Not needed on resource stop.

<ResponseField name="return" type="number">
  How many were removed.
</ResponseField>

```lua
exports.roadvr:clearRoadVrMarkers()
```
